## 1. Error：使用了比 minAppVersion 更新的 API

**审核原文**：`src/main.ts:110, src/main.ts:121, src/main.ts:135` — `obsidianmd/no-unsupported-api`

**代码核对**：三处都是同一个调用：

```ts
// src/main.ts:110, :121, :135
await workspace.revealLeaf(leaf);
```

**根因**：`Workspace.revealLeaf` 在 Obsidian **1.7.2 之前返回 `void`**，从 1.7.2 起返回 `Promise<void>`（见 `eslint-plugin-obsidianmd` 的 `obsidianDeclarationHistory`：`revealLeaf` 的 void 形态覆盖 `0.9.7–1.6.6`，Promise 形态从 `1.7.2` 开始）。插件声明 `minAppVersion: "1.5.0"`，扫描器按 1.5.x 的签名判定这三次 `await` 使用了更新版本的 API。

**为什么本地没复现**：本地用同一版 `eslint-plugin-obsidianmd@0.5.1` 的 `recommended` 配置扫描，没有报这条；商店扫描器用的是更严格的层/更新的判定数据。以商店结果为准。

**修复（推荐）**：把 `minAppVersion` 抬到 **`1.7.2`**，并在新版本对应的 `versions.json` 条目里写 `1.7.2`。当前 Obsidian 稳定版是 1.14.x，抬到 1.7.2 实际影响很小。

```json
// manifest.json
"minAppVersion": "1.7.2"

// versions.json（新版本 0.2.2 对应）
{ "0.2.2": "1.7.2" }
```

**备选**：去掉三处 `await`（改成 `void workspace.revealLeaf(...)`），保留 1.5.0。理论上 `await` 一个 `void` 是无害的，但商店扫描器可能就是按「是否使用 Promise 返回」判定的，去掉后仍可能被报；不如抬版本稳。

## 2. 目录要求：README 没有英文

**审核原文**：README does not appear to contain English text. The directory is primarily English-speaking. An English description is required, even if translations are also provided.

**代码核对**：属实。`README.md` 从标题到「限制」「开发」全部是中文，只有零散英文词（`Local`、`Git` 等），不构成英文说明。

**影响**：这是 warning 级别，但审核文案明确说「required」。不补的话，即使 Error 修了也可能被要求返工。

**修复**：把 README 改成**英文为主、中文附后**（或英文 `README.md` + 中文 `README.zh.md`，但目录只读 `README.md`，所以英文必须在根 README 里）。英文部分至少包含：

1. 一段 What it does
2. Install（release / 手动三件套）
3. Usage（打开面板、提交详情、diff 标签页、搜索、引用过滤）
4. Settings（四项）
5. **What this plugin accesses**（见第 6 节，主动披露 fs / child_process）
6. Limitations（桌面端、需要本机 git、只读）
7. Development / License

现有中文内容可以整体保留在 `## 中文` 小标题下，不必删。

## 3. Warning：设置页没有 `getSettingDefinitions()`

**审核原文**：`src/settingsTab.ts:12` — settings will not appear in Obsidian's settings search on 1.13.0+.

**代码核对**：属实。[`src/settingsTab.ts`](../src/settingsTab.ts) 只实现了 `display()`，没有声明式 `getSettingDefinitions()`。

**影响**：1.13+ 用户在「设置搜索」里搜不到这四项；不影响功能，影响评分。

**修复（可选，不建议现在做）**：`getSettingDefinitions()` 是 1.13 才有的 API。当前 `minAppVersion` 要抬到 1.7.2，引入 1.13 API 会再触发 `no-unsupported-api`，除非同时把 `minAppVersion` 抬到 1.13（会挡掉 1.7–1.12 的用户）或做运行时守卫。**建议先放着，等这条 warning 真的影响上架再说。**

## 4. Warning：设置回调返回了 Promise

**审核原文**：`src/settingsTab.ts:48-49, 79-80, 125-126` — Promise returned in function argument where a void return was expected.

**代码核对**：属实。三处 `persist(..., () => text.setValue(...))` 的箭头函数把 `text.setValue()` 的返回值直接返回了；在 Obsidian 的组件类型里这个返回值带有可链式的 `then`，被扫描器当成 Promise。

```ts
// 现在（3 处同样的写法）
this.persist({ gitPath: next }, () =>
  text.setValue(this.plugin.settings.gitPath),
);
```

**修复**：改成块体，不返回值：

```ts
this.persist({ gitPath: next }, () => {
  text.setValue(this.plugin.settings.gitPath);
});
```

第 79-80、125-126 两处同样处理。改动很小，能消掉 3 条 warning。

## 5. Warning：CSS mask 部分支持

**审核原文**：`styles/components.css:246, 247` — `css-masks` 在 Obsidian 1.4.5 上只是部分支持。

**代码核对**：属实。两行是：

```css
.visible-git-graph-svg-masked {
  -webkit-mask-image: linear-gradient(to right, black calc(100% - 24px), transparent);
  mask-image: linear-gradient(to right, black calc(100% - 24px), transparent);
}
```

**影响**：只是图谱右缘的渐隐装饰；即使不生效也不影响功能。

**修复（低优先级）**：去掉 `mask-image`，改成在容器上加一层 `linear-gradient` 覆盖层；或者保留（warning 不阻塞）。

## 6. Warning：fs / child_process（通用行为警告）

**审核原文**：

- Direct Filesystem Access：uses Node.js `fs` to access the filesystem outside the vault API. Can read and write any file.
- Shell Execution：executes shell commands via `child_process`.

**代码核对**：使用属实，但审核文案比实际严重：

- `node:fs` 只出现在 [`src/graph/watch.ts`](../src/graph/watch.ts)，只用 `existsSync`、`readFileSync`、`statSync`、`watch`，**没有任何写操作**（没有 `writeFile` / `unlink` / `mkdir` / `rename`）。
- `node:child_process` 只出现在 [`src/git/run.ts`](../src/git/run.ts)，用的是 `execFile(gitPath, args, {...})`，**没有 `shell: true`**，参数是数组，不存在 shell 注入。
- 读取的是仓库的 `.git`（当 vault 是仓库子目录时，这个目录在 vault 外）——这正是审核文案里 “outside of the Obsidian vault API” 的来源。

**影响**：这两条是桌面端 git 插件的固有属性，**无法消除**，也不会阻塞上架；但需要在 README 里主动披露，否则审核会一直带着这两条 warning。

**修复**：README 英文部分加一节 “What this plugin accesses”，逐条写明：只运行 `git` 的读命令（`log` / `for-each-ref` / `status` / `show` / `diff-tree` 等）、只读 `.git`、不写仓库、不联网、无遥测。

## 7. Recommendation：缺少 artifact attestation

**审核原文**：Missing GitHub artifact attestations for release assets (`main.js`, `styles.css`).

**代码核对**：属实。[`.github/workflows/release.yml`](../.github/workflows/release.yml) 没有 attestation 步骤。

**影响**：recommendation，不影响安装；会出现在 scorecard 的 "Passed checks" 里，做了更好。

**修复**：在 release workflow 加权限和步骤（官方推荐写法）：

```yaml
permissions:
  contents: write
  id-token: write
  attestations: write

# 在 Stage release files 之后、gh release create 之前
- name: Attest release assets
  uses: actions/attest@v4
  with:
    subject-path: |
      release/main.js
      release/styles.css
```

## 8. Recommendation：release 多了两个文件

**审核原文**：`versions.json`, `visible-git-graph-0.2.1.zip` — all other files will not be downloaded by Obsidian.

**代码核对**：属实。workflow 的 `gh release create` 传了 5 个附件；Obsidian 只用 `main.js`、`manifest.json`、`styles.css`。

**影响**：不阻塞；只是 recommendation。

**修复**：release 只传三件套，`versions.json` 留在仓库（Obsidian 从仓库读它做版本兼容判断），zip 不再上传。同时删掉生成 zip 的那一步。
